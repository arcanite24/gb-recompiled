# CR-M5-003 — Cross-check writable saves independently

Status: verified

Date: 2026-07-29

## Result

PASS. Four ROM-free save-fixture recipes were exported from a user-provided
Crystal save and compared through three independent boundaries:

1. the generated Crystal semantic accessors plus a separately implemented
   decoder;
2. unmodified Crystal's original Continue/load path in a freshly generated
   executable; and
3. PKHeX.Core invoked as an external test-only process.

Baseline, party nickname, active-box insertion, and backup-fallback fixtures
agreed on party, boxes, player data, badges, Pokédex state, and checksums. All
four original-game replays recorded zero interpreter fallback. A fixture with
both save checksums invalid was rejected.

The cross-check exposed and fixed two write/read contract bugs before writable
UI was allowed to proceed:

- active-box transactions now update both the bank-1 working mirror and the
  selected permanent box in ERAM bank 2 or 3; and
- save-backed readers now validate both save copies, prefer a valid primary,
  fall back to a valid backup, and reject the save when neither copy is valid.

## Gate audit

- **Export/import fixtures without GPL linkage:** passed. The tracked manifest
  is ROM-free, its exporter uses generated accessors, and PKHeX is a pinned
  process-only oracle.
- **Party:** passed for baseline, mutated nickname, and backup selection.
- **Boxes:** passed for all 14 decoded boxes and a transaction inserting the
  party Pokémon into the selected permanent box and working mirror.
- **Player data and badges:** passed across generated, independent, guest, and
  PKHeX views.
- **Pokédex:** passed for caught and seen species.
- **Checksums and backup selection:** passed for primary, backup fallback,
  original-game repair, and the both-invalid rejection control.
- **Original load path:** every positive fixture reached Continue and emitted
  the expected live WRAM with zero fallback.
- **Vanilla regression:** the exact fresh executable passed the full route.

## Limits

- PKHeX is an independent structure decoder, but not an oracle for Crystal's
  backup-selection algorithm. The original game is the independent oracle for
  that policy; PKHeX checks the guest-repaired output.
- The fixtures cover baseline export, one party edit, one active-box edit, and
  the two checksum-selection boundaries. They do not yet constitute the
  movement/sorting/cancel matrix required by CR-M5-004.
- No writable service is exposed through the port-module ABI yet. Native PC
  browsing and organization remain CR-M5-004.
