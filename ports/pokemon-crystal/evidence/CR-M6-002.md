# CR-M6-002 — Apply data overlays without rewriting the ROM

## Result

PASS. A validated Crystal encounter package now compiles into a private,
exact-ROM overlay artifact that the generated runtime can enable at startup.
The runtime resolves cartridge data reads through immutable overlays without
changing `GBContext.rom`. Omitting the option runs the same executable through
the original accurate path.

The gameplay tracer bullet changes all seven Route 29 encounter slots, across
morning, day, and night, to level-5 Hoppip. This broad proof fixture guarantees
that the locked route selects modified data; it is not presented as a balanced
sample mod.

## Runtime overlay boundary

The public runtime API is `runtime/include/gbrt_data_mod.h`. Its v1 artifact
loader:

- validates magic, ABI version, exact header size, exact ROM size and SHA-256;
- rejects empty/excessive entry sets, truncation, trailing bytes, out-of-range
  entries, unordered or overlapping entries, excessive patch bytes, and
  changed expected source bytes;
- builds a temporary immutable entry set and publishes it only after every
  entry passes;
- unloads any prior overlay on every failed load;
- leaves the owned original ROM allocation unchanged; and
- exposes overlaid and explicit-original physical-ROM reads.

Normal mapped CPU reads, OAM DMA, and HDMA use the overlaid view. Cartridge
identity, mapper/header setup, persistence compatibility, and ROM hashing
continue to use the original allocation. Live semantic ROM readers use the
overlay; `gbrt_semantic_reader_init_live_original` retains the exact original
view. Differential mode loads the same artifact into generated and interpreted
contexts before comparison.

The generated executable accepts `--data-mod <artifact.gbdm>`. It loads after
the embedded ROM is copied into the context and before port-module activation
or guest execution. No option means no overlay.

## Crystal semantic compiler

`tools/compile_crystal_data_mod.py` consumes the trusted M6-001 resolution and
the user's exact Crystal Rev 1 ROM. It rechecks the resolution contract hashes,
package order and identity, manifest/content hashes, exact ROM, and reviewed
encounter-table signature. Package content names map, time, slot, level, and
species; it cannot provide physical addresses.

The first reviewed target supports:

- map `ROUTE_29`;
- `morning`, `day`, `night`, or `all`;
- slots 0–6;
- levels 1–100; and
- the species already represented by the Route 29 table.

Unknown fields or identities, duplicate changes, unsupported targets, and a
changed source signature fail closed. The compiler emits sorted expected and
replacement byte pairs plus exact ROM and deterministic package-set hashes.

## Limits and next work

- Applied content is intentionally limited to Route 29 encounters. Trainer,
  rule, accessibility, and host-asset targets remain admission-only.
- The `.gbdm` artifact contains package-set identity material, but replay and
  diagnostic provenance do not record or enforce it until CR-M6-003.
- This proof fixture is infrastructure evidence. CR-M6-004 will ship two
  independently useful, composed sample mods.
- There is no in-game package manager or hot reload. Activation is a
  process-start option.
- The supported compiler emits only reviewed data ranges. Native behavior
  replacement remains the separate exact-ROM native-patch SDK.
