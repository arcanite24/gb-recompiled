style. No ROM-derived graphics are stored in the source tree.

## Contract and fallback

`GBPresentationMapState` now owns up to 32 semantic sprites with world pixel
coordinates, dimensions, stable sprite identity, project-owned color,
visibility, explicit low/normal/high priority, and a background-occlusion
requirement. This is distinct from the captured hardware OAM endpoint.

`gbrt_presentation_compose_widescreen` composes into a caller-owned
`uint32_t` surface. It first verifies that every camera-covered 32-pixel block
belongs to a submitted current or adjacent region. It returns a conservative
accurate-path disposition without writing output for:

- invalid scene, ABI, surface, or semantic sprite state;
- an uncovered camera edge;
- an active map transition or unclassified raster effect;
- an LCD-off accurate frame; or
- a visible sprite requiring unmodeled grass/under-tile occlusion.

Low, normal, and high sprites compose in deterministic priority/input order.
The compositor reads the captured frame only. Its tests copy the full frame
before composition and prove that semantic inputs and accurate PPU pixels are
unchanged afterward.

Crystal currently activates only for New Bark Town map group 24, map 4. It
validates the pinned New Bark and Route 29 map attribute dimensions,
connection masks, west-connection target ID/width, block banks/pointers, and
the live location before filling the generic contract. Unknown maps and any
layout disagreement fail closed.

## Limitations

- This is a bounded New Bark / Route 29 composition prototype, not a general
  Crystal world renderer.
- The project-owned procedural block style proves topology and sprite
  composition; it is deliberately not final replacement art.
- Grass and under-tile foreground masks are not modeled, so those object
  states correctly retain the accurate output.
- The compositor is a headless CPU reference. M7-003 owns higher-resolution
  replacement assets, host graphics-stack performance, and selected native UI
  and battle effects.
