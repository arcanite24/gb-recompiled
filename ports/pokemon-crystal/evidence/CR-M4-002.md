# CR-M4-002 — Generate read-only typed accessors

Date: 2026-07-29

## Result

PASS. Crystal generation now emits a bounded, exact-ROM, read-only C API for
location, party summary, badges, and Pokédex progress. The public API uses
semantic readers and typed values; it does not expose `GBContext`, generated
function names, or raw generated-runtime fields.

The same accessors support two explicit and non-interchangeable modes:

- `GB_SEMANTIC_READ_LIVE` reads exact physical ROM, external RAM, WRAM bank,
  or RTC locations from a live runtime reader.
- `GB_SEMANTIC_READ_SAVE` reads exact external-RAM offsets from a complete
  32 KiB battery image.

A mode mismatch fails before the backing callback runs. The generic reader
also checks ABI and exact ROM identity, while each generated view fixes its
space, bank, address, width, and output type.

## Crystal live/save mappings

The save aliases come from the pinned `pokecrystal` WRAM/SRAM layout and its
`SavePlayerData` / `SavePokemonData` copy routines.

| View | Live WRAM bank 1 | Save SRAM bank 1 | Width |
| --- | --- | --- | ---: |
| location and coordinates | `dcb5` | `a843` | 4 |
| badges | `d857` | `a3e5` | 2 |
| party | `dcd7` | `a865` | 296 |
| Pokédex caught/seen | `de99` | `aa27` | 64 |

These are separate persisted regions: location belongs to `sCurMapData`,
badges to `sPlayerData`, and party/Pokédex to `sPokemonData`. The generator
does not assume that WRAM is copied into one contiguous save block.

## Generated API

`generate_semantic_accessors.py` deterministically emits:

- `semantic/crystal_semantic.h`;
- `semantic/crystal_semantic.c`;
- typed `CrystalLocation`, `CrystalParty`, `CrystalBadges`, and
  `CrystalPokedexProgress` values;
- exact-size `crystal_semantic_read_view`; and
- one typed accessor per exposed view.

The generated source is compiled into the fresh project's `gbrt` target, and
the header/source hashes are recorded in `crystal-generation.json`.

## Fail-closed controls

Focused tests prove rejection of:

- reader ABI mismatch;
- exact-ROM mismatch;
- live/save mode mismatch;
- wrong WRAM bank;
- wrong typed output size;
- invalid save bank, space, or width in the package;
- truncated backing ranges; and
- a party count above Crystal's capacity of six.

The runtime reader addresses physical memory directly and does not depend on
the cartridge's currently selected ROM, SRAM, or WRAM bank.

## Independent Crystal result

The fresh route's `03-pc-save/state.json` supplied all 4096 bytes of live WRAM
bank 1. Its isolated `pokemon_crystal.sav` supplied the corresponding complete
32 KiB save image. The compiled generated accessors and a separate Python byte
decoder agreed on every exposed field, and live/save results were identical:

- map group `26`, map `5`, position `(8, 1)`;
- party count `1`, first species `155`;
- `0` Johto and `0` Kanto badges;
- `1` caught and `6` seen Pokédex entries.

The decoder uses hard-coded independently reviewed WRAM/save offsets rather
than calling or importing the generated accessor implementation.

```bash
cmake -G Ninja -B build . -DBUILD_TESTS=ON
ninja -C build
ctest --test-dir build --output-on-failure

python3 ports/pokemon-crystal/scripts/generate.py \
  --output output/pokemon-crystal-m4-semantic-20260729

cmake -G Ninja \
  -C output/pokemon-crystal-m4-semantic-20260729/crystal-build-profile.cmake \
  -S output/pokemon-crystal-m4-semantic-20260729 \
  -B output/pokemon-crystal-m4-semantic-20260729/build
ninja -C output/pokemon-crystal-m4-semantic-20260729/build

python3 ports/pokemon-crystal/scripts/validate_route.py \
  --manifest ports/pokemon-crystal/route/manifest.json \
  --executable \
    output/pokemon-crystal-m4-semantic-20260729/build/pokemon_crystal \
  --generation-receipt \
    output/pokemon-crystal-m4-semantic-20260729/crystal-generation.json \
  --evidence-dir \
    logs/pokemon-crystal/CR-M4-002/route-full-20260729 \
  --fallback-policy ports/pokemon-crystal/route/fallback-policy.json

python3 ports/pokemon-crystal/scripts/verify_semantic_accessors.py \
  --state \
    logs/pokemon-crystal/CR-M4-002/route-full-20260729/03-pc-save/state.json \
  --save \
    logs/pokemon-crystal/CR-M4-002/route-full-20260729/persistence/pokemon_crystal.sav \
  --accessor-dir \
    output/pokemon-crystal-m4-semantic-20260729/semantic \
  --output-dir \
    logs/pokemon-crystal/CR-M4-002/fresh-semantic-verification-20260729
```

## Limits

- These accessors are observational. Validated writes belong to M5.
- M4-002 exposes party count/species, not every party-record field.
- M4-003 still needs to define the versioned frontend/module lifecycle that
  receives a semantic reader without coupling headless execution to SDL or
  ImGui.
