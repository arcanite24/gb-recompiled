## Results

The recompiler has two explicit policies:

- `infer-boundaries`, retained as the general CLI default for compatibility;
- `names-only`, selected by Crystal's port-owned generator.

The parser-policy test proves that names-only returns no analyzer annotations
for an ordinary symbol file, preserves the legacy inferred policy, retains
separately authored annotations, rejects malformed records, and preserves
same-address source aliases. The complete repository suite passed 42/42,
including `native_patch_sdk_end_to_end`. The CLI rejected an unknown policy.

```text

58456 address records
```

```text
Analyzer boundary inputs: 0
(0 explicit annotations, 0 inferred from address symbols)
```

The annotated control reported exactly one explicit boundary and zero inferred
symbol boundaries. Its fixture identifies the disassembly-confirmed,
unreferenced one-byte `ret` function `IntroMenu_DummyFunction` at `01:5b04`.

## Gate audit

- **Explicit names-only policy:** the CLI and public API distinguish naming
  from inferred analyzer guidance. Crystal records `names-only` in its
  generation receipt.
- **Only trusted annotations add boundaries:** the raw symbol import adds zero
  boundaries. A separately supplied annotation adds exactly one boundary with
  `annotation` provenance.
- **Rich names survive:** canonical emitted names remain deterministic, while
  metadata's `source_symbols` array preserves every same-address alias.
- **No symbol-seeded speculative functions:** the generation log reports zero
  inferred address-symbol boundaries despite importing 53,784 addresses.
- **Controlled boundary delta:** the comparator rejects any added, removed, or
  renamed common function beyond the expected annotation.
- **Generated behavior:** the fresh names-only executable builds, matches the
  prior boot state, and passes the complete route without fallback.
- **Artifact boundary:** the ROM, upstream symbols, generated projects, saves,
  route captures, and raw logs remain ignored.

## Negative result and limits

A reachable-only, aggressive-scan-off diagnostic generation built and matched
the 121-frame boot state, but the complete route failed in `02-adventure` with
an incomplete fallback inventory. It accumulated 3,082,905
`bank_not_compiled` fallback entries. That profile is retained under
`logs/pokemon-crystal/CR-M3-002/route-20260729/` as evidence that Crystal must
keep all-bank analysis and aggressive scan enabled until later annotations
and unresolved-analysis metadata can replace their coverage safely.

Accordingly:

- names-only prevents symbols from seeding boundaries, but it does not yet
  make Crystal's overall analyzer graph narrow;
- the broad graph still contains 127,806 discovered functions and remains a
  correctness/build-footprint problem for CR-M3-004 and CR-M3-005;
- `source_symbols` preserves aliases but does not assign memory spaces,
  widths, lifetimes, or active semantic views; that is CR-M3-003;
- the policy fixture is not a production Crystal annotation set;
- this item does not promote any hook candidate to a stable native contract.
