# CR-M8-001 — Prove a wild-battle mutation tracer

## Result

PASS. GB Recompiled now exposes gameplay-mutation ABI v1: an exact-ROM,
stable-hook, typed-field contract that stages, validates, and atomically
commits a bounded pre-hook mutation. Pokemon Crystal consumes it at
`LoadEnemyMon` (`gbfn:v1:000f:68eb`) and changes only `wCurPartyLevel` before
the generated original derives enemy level, HP, and battle stats.

The Crystal source package contains no ROM or generated game source. Omitting
the native-patch manifest produces the ordinary no-dispatch build.

## Public contract and failure behavior

The public header is `runtime/include/gbrt_gameplay_mutation.h`; implementation
is `runtime/src/gbrt_gameplay_mutation.c`. The CLI advertises
`gameplay_mutation: 1` and `bounded-gameplay-mutations` in `--version-json`.
The Crystal standalone SDK contract pins the updated runtime tree.

The contract accepts one to eight named `uint8_t` semantic fields in v1. It
requires the pre phase, exact binding ROM identity and stable function ID,
exact request/spec field correspondence, and declared value ranges. All writes
are staged in one semantic transaction, the staged bytes and optional
port-owned validator must pass, and only then are the bytes committed.

`gameplay_mutation_is_atomic_and_fail_closed` proves:

- adjacent valid fields commit together and publish one bounded dirty range;
- wrong phase, wrong ROM, wrong hook, and out-of-range input do not write;
- external validation rejection publishes `validation_failed` without a live
  write; and
- an unwriteable field aborts the transaction without committing the earlier
  staged field.

`native_patch_sdk_end_to_end` additionally proves that a rejected optional
mutation can return success to the wrapper, run the generated original exactly
once across its safepoint, run post once after the matching guest return, and
leave the rejected field unchanged. Runtime ROM tampering remains a fatal
native-patch identity error before callback execution.

## Legal and privacy boundary

Tracked files contain only source, manifests, scripts, documentation, and
ROM-free hashes. ROM bytes, generated game source, executables, saves, RTC
files, and complete machine states remain in ignored private output/evidence
directories. A scan of the retained `result.json` found no `/Users`,
`/Volumes`, `roms/`, or ROM filename path.

## Limits and next work

- This is intentionally a fixed `+3`, cap-100 tracer, not the final Challenge
  Ruleset v1.
- Only wild initialization is bound. CR-M8-002 must prove the separately
  guarded trainer-party lifecycle.
- There is no persisted configuration or controller UI yet; package omission
  is the S01 disabled path.
- The route proves one locked wild encounter, not all species, levels, or game
  progression.
