# CR-M8-003 — Challenge Ruleset v1

Status: verified

Date: 2026-08-01

## Result

PASS. Both exact-ROM battle hooks now consume one pure, deterministic
`challenge-v1` calculation. The result uses the authored opponent level, the
strongest conscious player-party level, total Johto/Kanto badge progress, a
bounded signed offset, and hard minimum/maximum levels. It produces a stable
game-agnostic policy-result envelope before the existing exact-ROM mutation
contract stages the one reviewed guest field.

The retained zero-badge route proves the complete calculation in generated
Crystal executables:

- Wild: `max(original 2, strongest 5 + floor(0 / 4) + offset 3) = 8`.
- Trainer: `max(original 5, strongest 7 + floor(0 / 4) + offset 3) = 10`.

Both generated originals then derive coherent enemy/party statistics from the
new level. Each run retains zero interpreter fallback and commits only banked
WRAM bank 1, `$D143`, width 1.

## Rule contract

`GBGameplayMutationPolicyInput` and `GBGameplayMutationPolicyResult` are
versioned runtime ABI types. The port remains the policy owner; GB Recompiled
defines only the typed scalar inputs, deterministic result fields, outcome,
and stable reason vocabulary.

`challenge-v1` applies:

```text
badge_adjustment = floor(total_badges / 4)
scaled_reference = strongest_conscious_level + badge_adjustment + offset
candidate = max(original_level, scaled_reference)
proposed = clamp(candidate, configured_minimum, configured_maximum)
```

The supported offset is −5 through +5, badge count is 0 through 16, and the
first ruleset uses level bounds 1 through 100. No conscious party member
preserves the original with reason `no-reference`. Invalid ABI, level, badge,
offset, or bound inputs return `invalid-input`; neither outcome opens a guest
transaction.

The result echoes every input and records baseline, badge adjustment, proposed
value, minimum/maximum clamp flags, outcome, reason, ABI, and policy ID. This is
the stable explanation shared by later diagnostics, provenance, and UI work.

## Unit and boundary evidence

`crystal_challenge_rules_are_bounded_and_deterministic` covers:

- authored-level and party-reference precedence;
- badge transitions at three and four badges;
- signed-offset underflow without lowering the authored encounter;
- configured minimum and level-100 maximum clamps;
- empty/all-fainted party preservation;
- invalid original/reference levels, badge counts, offsets, and bounds;
- 100 byte-identical repeated results for one input tuple;
- stable `applied`, `no-reference`, and `invalid-input` reason strings.

`crystal_challenge_trainer_guard_is_fail_closed` additionally exercises the
real Crystal reader against two party slots. A level-20 fainted member is
ignored; the same conscious member plus four badges yields level 24 from
`20 + 1 + 3`; empty and oversized parties preserve the original without a
transaction.

## Recompiler package improvement

Fresh generation initially failed because native-patch v1 could copy only
translation units; a private header used by two patch sources was omitted.
Native-patch packages now accept contained portable `.h`, `.hh`, `.hpp`, and
`.hxx` entries, copy them into generated projects, and compile only declared
C/C++ translation units. `native_patch_sdk_end_to_end` includes and builds from
such a header after relocating the complete generated tree, while the existing
path traversal, symlink escape, unsafe-name, and unsupported-extension controls
remain fail closed.

The failed generated attempts are retained as
`output/pokemon-crystal-m8-003-combined-v1` and
`output/pokemon-crystal-m8-003-trainer-v1`; they contain private generated
artifacts and are not release inputs.
