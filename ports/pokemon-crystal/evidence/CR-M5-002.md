# CR-M5-002 — Implement validated semantic write transactions

Status: verified

Date: 2026-07-29

## Result

PASS. GB Recompiled now exposes an exact-ROM, synchronous semantic transaction
lifecycle with begin, bounded staged writes, staged reads, validation, commit,
and abort. Dirty ranges are merged and capped at 16. The final transaction
sequence, outcome, and dirty ranges are emitted in deterministic state JSON.
External RAM is persisted atomically before staged ERAM or WRAM becomes live,
so validation rejection, explicit abort, and persistence failure expose no
partial guest or durable state.

Crystal's semantic package is now version 2. Its full party and active-box
records are the only writable views. Generated accessors validate Crystal
counts, species, list terminators, Pokémon structures, levels, party HP bounds,
encoded names, exact record sizes, primary and backup check values, and both
save checksums. Party edits stage live WRAM plus the primary and backup save
copies and recompute both checksums. The generated name helper maps a bounded
ASCII subset into Crystal's terminated 11-byte encoding.

## Runtime transaction contract

- `gbrt_semantic_transaction_begin` clones ERAM and WRAM into private staged
  buffers only after exact ROM identity succeeds.
- Writes are limited to external RAM, fixed WRAM, and banked WRAM. Each write
  must fit its hardware window and backing allocation.
- Overlapping or adjacent writes merge into a stable dirty range. A
  seventeenth disjoint range fails before its bytes are staged.
- A staged reader lets a game-owned validator inspect the complete candidate
  state through the same bounded semantic read ABI.
- Validation failure automatically ends the transaction with
  `validation_failed`; explicit abort records `aborted`.
- Commit requires successful validation. When ERAM is dirty, the complete
  staged battery snapshot passes through the CR-M5-001 atomic persistence
  boundary before any staged range is copied to live memory.
- Persistence failure records `commit_failed`, releases the stage, and leaves
  both live memory and the last known-good file unchanged.
- Transactions are synchronous safepoint operations. Guest execution must
  remain paused from begin through commit or abort.

## Crystal contract

| View | Live/durable layout | Transaction behavior |
| --- | --- | --- |
| `player.party` | WRAM `01:dcd7`, primary `01:a865`, backup `00:ba65`, 428 bytes each | stages all three copies and both save checksums |
| `storage.active_box` | ERAM `01:ad10`, 1,102 bytes | stages the exact active-box record |

Party and box validators require:

- count within 6 or 20 and an `0xff` species-list terminator;
- valid species IDs, with the Gen II egg list marker handled explicitly;
- active record species agreement, levels 1–100, and party HP not exceeding a
  nonzero maximum;
- terminated 11-byte OT and nickname encodings;
- exact 428-byte or 1,102-byte input size; and
- valid primary and backup check values 99/127 and little-endian additive
  checksums over their complete game-data payloads.

## Failure controls

Crystal save and proves:

- a valid party transaction updates live, primary, and backup copies;
- adjacent dirty ranges merge and metadata reports the final ranges;
- invalid party count, species, record size, box count, and checksum fail
  closed;
- unsupported name characters and overlong names are rejected;
- commit before validation is rejected;
- validation failure and explicit abort do not change live or durable bytes;
- injected persistence failure returns `GB_SEMANTIC_COMMIT_FAILED` without

## Limits

- This slice provides the runtime and generated Crystal write contract. It
  does not yet expose writable services through the v1 port-module table or
  ship the native PC UI; those remain CR-M5-004 after independent CR-M5-003
  cross-checks.
- A transaction is not safe to hold while guest execution continues. The
  caller must use a synchronous guest safepoint.
- Battery and RTC remain separate atomic files. Semantic ERAM transactions do
  not modify RTC, and no cross-file two-phase commit is claimed.
- The no-op user-save probe proves that the current real save is accepted and
  preserved. Independent writable-save equivalence with Crystal's original
  load path and an external Gen II checker is intentionally the next
  milestone, CR-M5-003.
