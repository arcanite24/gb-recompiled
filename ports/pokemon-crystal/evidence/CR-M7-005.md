# CR-M7-005 — Add first-run ROM selection and local generation

Status: verified

## Result

PASS. GB Recompiled now exposes a versioned, path-free JSON Lines generation
progress protocol plus a caller-selected stable output prefix. Crystal's
first-run entry point uses a native file picker or explicit headless input,
checks the complete exact-ROM identity before creating a cache, generates and
builds only in a private per-user cache outside the source tree, and retains
no selected source path.

The final exact-ROM run generated, configured, built, and completed a
120-frame headless smoke. An independent audit found zero selected-path
matches across the complete cache, six valid launcher events, six valid
recompiler events, and no telemetry. The final ejected public tree contained
156 audited files including its inventory manifest.

## Recompiler protocol

`gbrecomp --progress-json <file>` emits schema
`gbrecomp.progress` version 1. A successful single-ROM generation reports the
ordered stages `rom-validated`, `analysis-complete`, `ir-complete`,
`code-generation-complete`, `output-complete`, and `complete`. Failures use
enumerated stage and error codes rather than dynamic messages. Records contain
no ROM name, source path, output path, title, or arbitrary tool error text.

`--output-prefix pokemon_crystal` fixes the generated target, filenames,
save ID, and metadata ROM name independently of the user-selected filename.
The generic regression proves this with a deliberately private synthetic
filename and also proves that a malformed ROM creates no output and emits only
`rom-invalid`.

## First-run and privacy boundary

`scripts/first_run.py` validates size, SHA-1, SHA-256, and MD5 locally before
creating any cache directory. It refuses a cache inside the source checkout,
uses a process umask of `077`, generates to the stable
`generated/crystal-rev1-v1` identity, suppresses ordinary child-process
output, and writes only two safe progress streams plus hash-only receipts.

The first-run receipt explicitly records that telemetry is disabled, the
source path is not retained, and no save is included. The selected path was
scanned as raw bytes across every file in the completed cache with zero
matches. All 41 audited cache directories were private. A 120-frame smoke
wrote its state and save/RTC only inside that private cache; the state SHA-256
is `a366fae34a88b5f165e3073e0fda835346594d6e18754205ee4c564ab1118123`.

The unsupported-ROM regression uses a same-size 2 MiB input, exits with stable
code `unsupported-rom`, creates no cache, and discloses neither its filename
nor path.

## Limitations

- The exact end-to-end proof is macOS arm64. Windows, Linux, packaged launcher
  relocation, controller-first operation, and uninstall/save preservation are
  CR-M7-006.
- The headless `--rom` selection path was used for deterministic automation.
  The same validator backs the native Tk file picker, but its visual interaction
  was not part of this automated proof.
- This gate builds from source on first run. It does not claim that Release
  compilation latency is final product quality.
