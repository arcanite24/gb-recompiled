## Method

The runtime now records a complete, cause-aware fallback inventory independent
of the optional hotspot display limit. Each site includes reason, bank/address,
entry count, interpreted instruction count, cycles, first/last frame, and
dispatch metadata. Inventory overflow is reported as incomplete and fails the
Crystal route validator.

Control-flow instructions previously returned from the interpreter before
closing the diagnostic session. That made entry, instruction, and cycle totals
incomplete. A repository-owned regression now runs an interpreted `JR +0` and
requires one entry, one instruction, and 12 cycles.

The unclosed classification project was generated and built before the
route-derived entry-point file became the generator default:

```bash
python3 ports/pokemon-crystal/scripts/generate.py \
  --output output/pokemon-crystal-m2-fallbacks

cmake -G Ninja \
  -C output/pokemon-crystal-m2-fallbacks/crystal-build-profile.cmake \
  -S output/pokemon-crystal-m2-fallbacks \
  -B output/pokemon-crystal-m2-fallbacks/build

ninja -C output/pokemon-crystal-m2-fallbacks/build
```

Its retained receipt records `analysis.entry_points: []`, which is the
pre-closure analyzer configuration. The route was then run with an empty
allowlist to make every observed fallback a fail-closed classification result:

```bash
python3 ports/pokemon-crystal/scripts/validate_route.py \
  --manifest ports/pokemon-crystal/route/manifest.json \
  --executable output/pokemon-crystal-m2-fallbacks/build/pokemon_crystal \
  --generation-receipt \
    output/pokemon-crystal-m2-fallbacks/crystal-generation.json \
  --evidence-dir \
    logs/pokemon-crystal/CR-M2-004/inventory-20260729 \
  --fallback-policy ports/pokemon-crystal/route/fallback-policy.json
```

The expected nonzero result enumerated the complete unexplained-site set after
all four route segments had run.

The 40-site union was checked into
`route/analysis-entry-points.json`. The generator hashes the file into its
receipt and passes every entry to `gbrecomp`. The port policy intentionally has
an empty retained-fallback allowlist.

Generate, build, and validate the closed project:

```bash
python3 ports/pokemon-crystal/scripts/generate.py \
  --output output/pokemon-crystal-m2-no-fallback

cmake -G Ninja \
  -C output/pokemon-crystal-m2-no-fallback/crystal-build-profile.cmake \
  -S output/pokemon-crystal-m2-no-fallback \
```

or writable-HRAM misses. All inventories were complete with zero dropped
sites.

## Gate audit

- Complete diagnostics: every dispatch cause has an explicit reason and
  bank/address; site totals include entries, instructions, cycles, frames, and
  relevant dispatch metadata.
- Full-route classification: all four checked-in route segments completed
  before policy evaluation; their complete inventories produced the 40-site
  union above.
- Zero unexplained fallback: the release route reports no fallback at all.
- Retained-fallback policy: the policy is explicit, checked in, hashed, and
  empty. Any newly observed site or stale allowed site fails validation.
- Artifact hygiene: the ROM, generated projects, raw captures, save data, and
  logs are ignored. Only the entry-point set, policy, tests, tooling, and this
  summary are repository material.

## Limits

- This proves the complete checked-in route, not every optional Crystal map,
  event, battle, or post-game path. Extending the route may expose additional
  analyzer roots and will fail closed until they are classified.
- The route validator checks deterministic state, frames, PCM, and fallback
  policy, but it is not an independent hardware oracle.
- Static analysis still reports conservative undefined or unresolved
  diagnostics outside the exercised route; this result does not claim that all
  ROM code is statically reachable.
- The fallback inventory has a fixed diagnostic capacity. Overflow is visible
  and rejected; no performance claim is made for the added instrumentation.
