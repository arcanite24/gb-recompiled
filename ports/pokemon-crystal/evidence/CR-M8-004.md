# CR-M8-004 — Versioned configuration and provenance

Status: complete on 2026-08-01.

## Outcome

Challenge Ruleset v1 now consumes a canonical, host-owned configuration that
is loaded and validated before any guest context exists. Missing configuration
selects the inactive path; malformed, non-canonical, schema-mismatched,
policy-mismatched, and out-of-range configurations terminate before guest
execution. An applied configuration survives process restart with the same
path-free SHA-256 identity in the state dump and Challenge diagnostics.

The reusable runtime contract is `gbrecomp.host-configuration` version 1. Its
canonical JSON records policy identity, explicit Apply state, enabled state,
offset, and lower/upper bounds. The runtime exposes strict parse/load/serialize
and atomic replace-on-write operations. Native-patch manifests declare the
accepted schema, version, policy, offset limit, and value range; the recompiler
rejects invalid declarations and emits the corresponding pre-execution
contract into generated projects.

The configuration is host data, not guest save data. Neither its filesystem
path nor its contents enter generated source, state provenance, or tracked
evidence; only the stable policy ID, booleans, and SHA-256 identity do.

## Legal and lifecycle boundary

Tracked configuration examples contain policy settings only. ROM bytes,
generated game source, executables, saves, RTC state, and full machine states
remain ignored private artifacts. Challenge configuration is separate from the
guest save and does not change its schema. The atomic writer is available to
the controller panel in CR-M8-005; that slice owns the interactive draft,
Apply, and Cancel flow.
