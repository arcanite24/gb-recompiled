# CR-M5-004 — Ship native PC browsing and organization

Status: verified

Date: 2026-07-29

## Result

PASS. The Crystal Workbench now contains a native PC surface that browses all
14 boxes, searches by species, sorts the selected box by species or level, and
moves Pokémon between the party and a selected box. Every edit uses an
explicit stage/confirm interaction. Back cancels the candidate without
starting a runtime transaction or changing the save.

Port ABI v2 adds a one-shot semantic-edit service. The runtime owns transaction
begin, commit, and abort; a reviewed source-built module receives an ephemeral
staged transaction only while its callback runs. Crystal's module holds copied
party and box records, never pointers into guest WRAM or banked ERAM.

Box-to-party movement reproduces Crystal's Gen II stat calculation, including
ceil-square-root Stat Experience and DVs. Party-to-box movement retains the
exact boxed 32-byte Pokémon structure. Both directions preserve species,
held item, moves, OT name, nickname, and level. Mail-bearing moves are rejected
without a write, matching the safe boundary until an explicit remove-mail flow
exists.

## Reusable runtime boundary

`GBPortServices` ABI v2 provides `run_semantic_edit` and an opaque service
token. The call:

1. verifies the module's expected exact-ROM identity;
2. begins a private staged semantic transaction;
3. invokes the module callback synchronously;
4. aborts when staging or validation fails; and
5. commits through the atomic battery boundary only after the callback returns
   a still-active validated transaction.

The service does not expose `GBContext`, guest pointers, SDL, ImGui, or the
generated function namespace. The transaction pointer is callback-scoped and
must not be retained.

## Crystal PC contract

- The current and all 14 canonical boxes are exposed through generated,
  bounded exact-ROM accessors.
- Legacy never-opened boxes encoded as `0xff` or zero-filled records normalize
  to empty only on read. Every authored record uses the strict count and
  terminator representation.
- Edits to the active box update its canonical record and working mirror.
  Edits to another box update only that canonical box.
- Transaction validation checks party copies, both save checksums, the active
  mirror/canonical pair, and every initialized canonical box.
- Stable sorting moves species list entries, complete 32-byte boxed Pokémon,
  OT names, and nicknames as one logical record.
- The UI prevents depositing the last party member, overflowing party or box
  capacity, and moving a mail-bearing Pokémon.

## Limits

- The native PC is opened through the Workbench toggle in this slice. Binding
  it to the verified `BillsPC` guest function is CR-M5-005.
- Search is species-based. Text-name search and box renaming are not included.
- Mail-bearing Pokémon are preserved by rejecting the move. A future native
  remove-mail/mailbox transaction would be required before allowing that move.
- Sort evidence includes multi-record portable matrices; the user route save
  contains one boxed Pokémon, so its generated UI sort is a valid one-record
  commit.
