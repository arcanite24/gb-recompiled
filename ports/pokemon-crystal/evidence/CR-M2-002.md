The raw route-result hashes differ because their exact command arrays contain
different evidence-directory paths. Those paths are intentionally not guest
inputs. The normalized comparison retains every runtime option and replaces
only artifact paths, so a changed frame limit, input, capture list, audio mode,
or other option still changes the comparison.

The 10-second PCM captures are interleaved stereo signed 16-bit samples at
44.1 kHz before host-device resampling. A representative capture contains
877,512 nonzero bytes across all 256 byte values; the matching hash does not
describe an all-zero silence fixture.

## Gate audit

- Three equivalent clean executions: the verifier requires at least three
  runs, gives each run a distinct empty persistence directory, and invokes the
  complete four-process route validator for each.
- Final state: all 35 asserted values match, including completed frames,
  64-bit total cycles, battle state, map identity, coordinates, status flags,
  and story state.
- Selected frames: all 12 required checkpoint IDs, frame numbers, and frame
  SHA-256 values match.
- Deterministic PCM: every segment captured the same bounded PCM byte count and
  digest in all three runs.
- Input identity: each segment's checked-in input-file digest and rendered
  input digest are part of the normalized comparison.
- Executable and metadata identity: executable, manifest, generation receipt,
  metadata, generated source inventory, recompiler, and runtime identities are
  recorded and compared.
- Feature flags: build profile, native-patch selection, references, and each
  normalized runtime command are retained in the aggregate result.
- Durable persistence: the final battery-save bytes match in all three runs.
- Fail-closed comparison: an injected final-state mismatch test proves that the
  verifier exits nonzero, does not write a passing result, and retains the
  first differing comparison path in a failure artifact.
- Real-time RTC input: each run isolates its RTC file in its own persistence
  directory. The `.rtc` file is explicitly excluded from byte comparison
  because it may encode host elapsed time; guest frames and asserted state
  remain strict comparables.

## Limits

- PCM capture is bounded to the first ten seconds of each process, not the
  complete multi-hour emulated route. Each process begins at the same title
  sequence, so the four per-run PCM captures intentionally have the same
  digest. Battle- and menu-specific audio windows remain future coverage.
- This evidence proves repeatability for one executable, exact ROM, build
  profile, input set, and host toolchain. It does not claim cross-platform
  determinism.
- Excluding `.rtc` bytes is an explicit isolation boundary, not proof of RTC
  determinism. Controlled RTC behavior and restart/corruption testing belong
  to CR-M2-005.
- Matching generated runs do not independently prove hardware accuracy or
  generated-versus-interpreter consistency. Those claims belong to CR-M2-003
  and CR-M2-006.
