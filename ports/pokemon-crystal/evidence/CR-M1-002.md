## Commands

Run twice from the repository root, changing only the fresh output suffix:

```bash
ports/pokemon-crystal/scripts/generate.py \
  --rom roms/selected_gbc_top10/pokemon_crystal.gbc \
  --gbrecomp build-crystal-m1/bin/gbrecomp \
  --runtime runtime \
  --symbols ports/pokemon-crystal/references/generated/pokecrystal11.gbrecomp.sym \
  --annotations none \
  --native-patch none \
  --output output/pokemon-crystal-m1-a \
  --build-type Release \
  --generated-compile-jobs 8 \
  --generated-opt-level 3 \
  --ipo off \
  --strip off \
  --codegen-jobs 0 \
  --scan on

ports/pokemon-crystal/scripts/compare_generated.py \
  output/pokemon-crystal-m1-a \
  output/pokemon-crystal-m1-b \
  --json-out logs/pokemon-crystal/CR-M1-002/comparison.json
```

The wrapper itself runs the exact-ROM verifier, verifies all nine pinned
reference sources, and regenerates the locked symbol input before invoking the
recompiler.

## Limits

- This item proves generation reproducibility, not that the generated project
  compiles or runs; that is the next gate.
- Aggressive analysis logged 10,948 undefined-instruction diagnostics and 595
  unresolved indirect jumps, then reported 127,767 functions and produced
  approximately 492 MiB of files, including 106 MiB of metadata. Generation
  is deterministic, but this is not credible code/data classification and
  must be narrowed by the analysis-and-metadata milestone.
- The comparison excludes only a post-generation `build/` root plus
  `.DS_Store` and `imgui.ini`, which are build or host UI state rather than
  generator outputs.
- The generated sources contain the user-provided ROM and remain ignored,
  local artifacts.
