# CR-M3-005 — Generate narrow trusted Crystal annotations

Date: 2026-07-29

## Result

PASS. Crystal now defaults to a narrow, reviewed annotation file containing
25 route-proven global functions and 13 exact semantic data ranges. It does
not convert unnamed mid-function recovery roots or aggressive-scan guesses
into trusted functions. All historical fallback and undefined-opcode sites
remain deliberately classified by CR-M3-004 diagnostics, and the complete
route is byte-identical at every normalized checkpoint and final-state field.

## Trust boundary

`annotations/crystal-route.annotations` contains:

- 24 named global functions exercised by the M2 route;
- the pinned `OAMDMACode` ROM source copied into the ten-byte HRAM overlay;
- the 13 map, party, Pokédex, checksum, and active-box address ranges from the
  reviewed semantic manifest.

The 15 unnamed route recovery roots remain in
`route/analysis-entry-points.json`. Treating them as functions would assert a
boundary the pinned source does not provide.

The annotation loader now:

- retains explicit data widths in generated metadata;
- rejects overlapping ranges;
- rejects ranges crossing a Game Boy memory-space boundary; and
- keeps annotation provenance separate from imported symbol names.

The generator consumes this file by default. `--annotations none` remains an
explicit unannotated control.

## Limits

- Annotation trust does not turn global symbols into public hook contracts.
  CR-M3-006 still has to prove callers, returning bodies, replay coverage, and
  stability under regeneration and chunk/name perturbations.
- The large false-code inventory is explicitly classified, not eliminated.
  Future narrowing should use source-backed ROM data ranges rather than bulk
  one-byte suppressions.
