# CR-M6-003 — Record mods in deterministic replay provenance

## Result

PASS. Modded replay is now represented by one portable, ROM-free JSON
envelope rather than an unbound input string. The envelope embeds the small
private overlay artifact and exact cycle-anchored inputs, records every
required provenance layer, and is validated completely before the replay
driver creates output or starts the guest.

Two independent output directories produced byte-identical diagnostic result
JSON and reproduction SHA-256
`918e72b68296b40200255640dfd82f942105a79464781a152a4fc9bbe5e3eb28`.
Package, order, content, schema, executable, configuration, and segment-order
mismatches all failed before a guest output directory existed.

## Portable manifest

The reusable creator is `tools/create_data_mod_replay.py`. Crystal's tracked
source seed is `ports/pokemon-crystal/replay/route29-seed.json`
(`4f8460790dec011f878e2cdb9cdee41769b5868baabfc7d25db69eaf9baae060`).
The seed names the game and exact ROM, fixes the headless runtime
configuration, and points to the established new-game and adventure inputs.
The creator confines and embeds those input bytes, so the emitted manifest has
no local source paths.

The final portable manifest is
`logs/pokemon-crystal/CR-M6-003/final-manifest-20260729/route29-replay.json`
(`8964904d3dc9794bee44b68031d10c37b309922df4196fac5d8fa1fbd672c869`).
It records:

- exact ROM SHA-256 and size;
- executable, generation receipt, and generated-source inventory SHA-256;
- overlay artifact bytes/hash and canonical package-set hash;
- ordered package ID/version/order and manifest SHA-256;
- every content ID, target, and SHA-256;
- target-policy, package-schema, semantic-manifest, and semantic-schema
  SHA-256;
- the complete fixed runtime configuration and canonical configuration
  SHA-256;
- exact input bytes/hashes, segment order, frame limits, capture frames, and
  selected frame/state oracles; and
- portable-seed SHA-256
  `d50de00b97ce4346295c5a6924517364bfebc10501b3eb122e92d3edf8376f75`.

The manifest embeds only the 512-byte private `.gbdm` artifact and replay
inputs. It contains no commercial ROM and still requires the user to supply
the exact supported ROM at replay time.

## Fail-closed preflight

`ports/pokemon-crystal/scripts/verify_data_mod_replay.py` validates before it
creates `--output`:

- exact manifest shape and schema version;
- user ROM size/hash;
- executable, receipt, receipt ROM, and source-inventory hashes;
- the supported canonical runtime configuration and its hash;
- ordered package structure, identities, content hashes, load order, and
  canonical package-set hash;
- all four schema/contract hashes;
- embedded artifact hash, magic, ROM binding, and package-set binding;
- exact two-segment order, bounded frame configuration, input base64/hash and
  JSON shape, expected frame/state shape; and
- the canonical portable-seed hash.

Only then does it materialize the private artifact and inputs, start the two
process-separated segments, and check frames, selected state, and zero
fallback. The diagnostic result repeats all provenance except embedded binary
payloads and adds a path-independent reproduction hash.

## Repository gate

`tests/test_data_mod_replay.py` builds a legal synthetic ROM, executable,
receipt, artifact header, package set, configuration, and two-segment replay.
It accepts the complete matching envelope and rejects order, content,
configuration, and executable mismatches without commercial inputs. The root
suite also retains the M6-001 manifest and M6-002 overlay/compiler gates.

## Limits and next work

- The replay envelope binds one exact executable. A different local build must
  intentionally record a new replay identity even if its behavior is
  equivalent.
- The manifest is integrity-checked, not signed. Editing it and consistently
  recording a new set of hashes creates a different replay identity.
- The current replay driver is Crystal-specific because selected state oracles
  are game-semantic. Manifest creation and provenance structure are generic.
- CR-M6-004 will use the same envelope to prove two independent packages alone
  and in deterministic composition.
