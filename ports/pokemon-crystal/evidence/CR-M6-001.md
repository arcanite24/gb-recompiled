# CR-M6-001 — Define the data-mod manifest

## Result

PASS. GB Recompiled now has a ROM-free data-mod package v1 contract, a
Crystal-specific allowed-target policy, and a whole-package-set validator.
Validation resolves identity, exact compatibility, deterministic order,
dependencies, conflicts, file hashes, confined paths, and provenance before
producing a trusted resolution artifact.

This slice defines and validates packages only. Overlay application without
ROM rewriting is CR-M6-002.

The generic manifest requires:

- reverse-domain-like package ID and strict three-component semantic version;
- data-mod runtime ABI `gbrecomp.data-mod` v1;
- exact port version, ROM size/hash, semantic package/version/hash, and
  semantic schema hash;
- numeric load order, exact-version dependencies, and explicit conflicts;
- SPDX-style license, nonempty authors, HTTPS source, and declared content
  origin; and
- stable content IDs, known target IDs, confined relative paths, and lowercase
  SHA-256 hashes.

The JSON Schema was checked as valid Draft 2020-12.

## Crystal policy

The policy locks Pokémon Crystal UE Rev 1 and semantic package v2. Its initial
safe targets are:

- `crystal.encounters.v1`;
- `crystal.trainers.v1`;
- `crystal.rules.v1`;
- `crystal.accessibility.v1`; and
- `crystal.host-assets.v1`.

Targets specify media intent, allowed extensions, and maximum bytes. The host
asset target permits only project-original or compatibly licensed package
provenance. The v1 contract permits no executable code, arbitrary guest
addresses, ROM replacement data, path escape, or unknown target types.

## Composition and fail-closed behavior

The validator processes the complete installed set in one invocation. Package
IDs must be unique. Every exact dependency must be installed at its declared
version and load earlier than the dependent. Any installed declared conflict
rejects the set. Successful ordering is the stable tuple `(load order,
package ID)`.

Content paths must be canonical descendants of the manifest directory.
Absolute paths, `..`, backslashes, missing files, and symlinks reject.
Extensions, sizes, and hashes are checked against the target policy.

The output file is removed before validation and written through a temporary
file only after the entire set passes. A rejected update therefore cannot
leave a stale resolution that a launcher could mistake for current trusted
state.

## Limits

- The validator is a preflight/resolution tool; the runtime does not consume
  or apply its output until CR-M6-002.
- Dependencies use exact semantic versions in v1. Version ranges are excluded
  to keep resolution deterministic and auditable.
- Per-target content field schemas and overlay semantics belong to the first
  real consumer in CR-M6-002; this slice validates package containment and
  target admission, not gameplay interpretation.
