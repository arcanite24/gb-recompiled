# CR-M3-004 — Export unresolved analysis decisions

Date: 2026-07-29

## Result

PASS. The generated metadata now contains stable, structured, actionable
records for conservative or unresolved analyzer decisions. The Crystal
validator maps every historical M2 fallback target and every current
undefined-opcode site to metadata without reading generated C or relying on
console output as the contributor interface.

## Contract

Each `analysis_diagnostics` record has:

- a stable `analysis:v1` ID;
- kind, bank, address, and memory space;
- status and human-readable evidence;
- a concrete next annotation or entry-point action;
- a fallback, false-code, copied-ROM, or dispatch relationship; and
- an optional related bank/address for source-to-target relationships.

The emitted kinds are:

- `unresolved_indirect_jump`;
- `unresolved_direct_target`;
- `ram_overlay`;
- `manual_entry_point`;
- `uncertain_entry_point`;
- `data_as_code_candidate`; and
- `undefined_instruction`.

Records are deduplicated by stable identity, retained through IR, and emitted
in deterministic ID order.

## Limits

- Analyzer diagnostics describe conservative static decisions; they are not
  proof that a candidate is code or data.
- The 10,522 undefined sites expose the cost of all-bank aggressive scanning.
  M3-005 must classify or eliminate the false-code roots with narrow trusted
  annotations rather than treating this count as acceptable release quality.
- Runtime fallback records are dynamic evidence. The generated metadata maps
  the historical route inventory to the entry points that closed it, while
  the current route independently proves zero fallback.
