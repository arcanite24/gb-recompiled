# CR-M6-005 — Extend native module composition only from real demand

Status: verified

## Result

PASS. Crystal Recompiled now supports a bounded, deterministically ordered set
of source-built native extensions around its one exact-ROM Workbench module.
The first consumer is
`org.gbrecompiled.crystal.encounter-lens@1.0.0`: an observational host panel
that reads the current Route 29 map/time and seven live encounter slots,
including an active data overlay.

This is real capability beyond the data-mod contract. A startup byte overlay
can change reviewed ROM data but cannot receive host input or continuously
render derived live state. Static source-built composition was retained.
Dynamic native loading and sandboxed bytecode were evaluated and rejected for
this use case in `NATIVE_EXTENSIONS.md`.

## Composition and fail-closed contract

Port extension ABI v1 retains at most 16 descriptors. Generation validates
exact host/ROM/ABI identities, source hashes, the bounded
`host-draw`/`host-input`/`semantic-read` capability set, dependencies,
conflicts, duplicate identities, and confined sources. It sorts by
`(priority, extension ID)`, emits a static registry, and records the ordered
set in the generation receipt.

The runtime repeats the registry ABI, descriptor identity/version/priority,
exact ROM, count, and strict order checks before base activation. Base
activation precedes extensions; extension lifecycle and dispatch use resolved
order, while rollback and detach use reverse order. A descriptor/registration
mismatch makes the generated executable fail before guest execution.

Extensions receive a reduced service view. The runtime clears
`semantic_edit_user` and `run_semantic_edit`, and exposes no `GBContext`,
guest-memory pointer, generated function call, SDL/graphics API, filesystem,
or network. The existing native-patch call-frame and
`gb_native_call_original()` safepoint contract is unchanged.

Portable tests cover reversed manifest arguments, priority ordering, missing
dependencies, conflicts, duplicate/unknown/escaping content, capability
escalation, source/ROM/host/ABI mismatch, ordered callback rendering,
observational guest state, and runtime descriptor mismatch.

## Gate audit

- Real authoring capability: PASS; live derived host input/rendering cannot be
  represented by a startup data overlay.
- Deterministic composition: PASS; validation, generation receipt, registry,
  runtime dispatch, state output, and synthetic two-extension rendering have
  one stable order.
- Fail closed: PASS; package, capability, dependency/conflict, source,
  identity, registry, and runtime descriptor controls reject before guest
  execution.
- Replay provenance: PASS; the final verifier checks the ordered
  manifest/source receipt plus executable and data-overlay identities before
  replay.
- Exact-ROM and safepoint contracts: PASS; the runtime rechecks the ROM and
  extensions cannot receive semantic writes or native-patch call state.

## Limits

- Extensions are reviewed source compiled into a generated project; changing
  the installed native set requires regeneration and a platform build.
- The static C shares process trust with the generated executable. The bounded
  service view reduces authority but is not an operating-system sandbox.
- Dynamic libraries and portable bytecode are not implemented.
- Encounter Lens currently recognizes the one reviewed Route 29 encounter
  table and displays numeric species IDs; broader semantic encounter metadata
  requires a later, evidence-backed contract.
- This proves the established Crystal route and host-command output. It is not
  a claim of whole-game compatibility or graphical validation on every
  platform.
