## Commands

Generate and build the current differential-capable project:

```bash
python3 ports/pokemon-crystal/scripts/generate.py \
  --output output/pokemon-crystal-m2-differential

cmake -G Ninja \
  -C output/pokemon-crystal-m2-differential/crystal-build-profile.cmake \
  -S output/pokemon-crystal-m2-differential \
  -B output/pokemon-crystal-m2-differential/build

ninja -C output/pokemon-crystal-m2-differential/build
```

Run the strict boot window and the negative-control oracle:

```bash
output/pokemon-crystal-m2-differential/build/pokemon_crystal \
  --differential 100000 \
  --differential-log 25000 \
  --differential-fail-on-fallback \
  --log-file \
    logs/pokemon-crystal/CR-M2-003/acceptance-20260729/boot/differential.log \
  --dump-state \
    logs/pokemon-crystal/CR-M2-003/acceptance-20260729/boot/state.json

output/pokemon-crystal-m2-differential/build/pokemon_crystal \
  --differential 1000 \
  --differential-fail-on-fallback \
  --differential-inject-mismatch 10 \
  --log-file \
    logs/pokemon-crystal/CR-M2-003/acceptance-20260729/self-test/injected.log
```

The second command must exit nonzero. Its retained diagnostic identifies the
injected A-register difference at step 10.


Capture one post-new-game persistence seed, then capture complete machine state
at the three later windows:

```bash

  "$raw/start-menu/persistence"

"$game" --headless --no-audio --limit-frames 12050 \
  --input "$new_game_input" \
  --save-state-file "$raw/seed/new-game-final.gbs" \
  --save-dir "$raw/seed/persistence" \
  --log-file "$raw/seed/capture.log"
```

```bash
"$game" --no-audio \
```

## Gate audit

- Strict generated-versus-interpreter comparison: all positive commands retain
  full mutable-memory and device comparison; none uses
  `--differential-no-memory`.
- Explicit fallback rejection: every positive window passes
  `--differential-fail-on-fallback`.
- Representative route coverage: boot starts from reset; the other three
  states come from the checked-in route at overworld, trainer battle, and
  Start-menu checkpoints.
- Bounded execution: every positive window compares exactly 100,000 scheduler
  steps and records the number of guest frame boundaries crossed.
- Seed identity: the same complete savestate is loaded into both contexts
  before comparison, and incompatible ROM/runtime/APU layouts fail before
  execution.
- Oracle self-test: a retained test-only CLI option perturbs interpreter state
  at an exact step; both current Crystal evidence and the synthetic CTest prove
  the comparator detects and locates the difference.
- No unexpected fallback: all four positive runs exit zero under strict
  fallback rejection.

## Limits

- Differential mode is not an independent hardware oracle. Generated and
  interpreter CPU paths share this project's PPU, APU, timer, DMA, mapper, and
  persistence implementations.
- The seeded windows are bounded samples, not lockstep comparison of every
  instruction in the complete route.
- Later seeds were captured with audio disabled, so their differential runs
  also use `--no-audio`. Loading those seeds with audio enabled fails closed
  with `Savestate APU layout mismatch`; the failed diagnostic attempts are
  retained in raw evidence. Boot differential uses the normal audio-enabled
  configuration.
- Seeded execution begins from a generated-path savestate. The comparison
  proves both paths agree after that shared state, not that the interpreter
  independently reproduced the entire route leading to the seed.
